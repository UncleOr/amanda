# הכל מצויר

הכיוון שאור נתן: **בסוף, כל מה שרואים במשחק צריך להיות גרפיקה שאנחנו
מייצרים.** היריות, הפיצוצים, האבק, הערפל, הרקעים, הקלפים, הכפתורים. הכל
צריך להיות יפה.

המסמך הזה הוא ספירת מלאי כנה: מה כבר מצויר, ומה עדיין מצויר *בקוד*.

## מה שכבר אמנות

| | מצב |
| --- | --- |
| קלפי מפלצות ופעולה | ✅ 51 קבצים, סגנון `darkcomic` |
| אמנדה — לוגו, פורטרט, באנר | ✅ מהקנון של עמוד 8 |
| צ'ופי | ✅ |
| רקעי זירה | ⚠️ שלושה קיימים (`rift`, `colosseum`, `swamp`), **רק `rift` בשימוש** |
| אייקונים | 🔄 בעבודה — 29 מוגדרים |

## מה שעדיין מצויר בקוד

כאן הפער. כל אלה מצוירים בזמן ריצה מצורות גיאומטריות, לא מקבצי אמנות:

**אפקטי הקרב** — `arenaFx.ts` ו-`Arena.tsx` מכילים **57 קריאות ציור**
(`circle`, `rect`, `poly`, `fill`). כל מה שקורה בקרב הוא עיגולים ומצולעים
עם צבע:

- **יריות** — `drawProjectile` מצייר עיגול או משולש שטסים
- **פיצוצים** — פרצי חלקיקים הם עיגולים קטנים מתפוגגים
- **אבק** — אותו דבר
- **הילות** — טבעות
- **מוות** — דהייה

**הערפל** — ענני CSS עם אנימציית `fogdrift`. יפה יותר מסימני שאלה, אבל זה
עדיין `radial-gradient`, לא ציור.

**הכפתורים, המסגרות, הרקע הכללי** — הכל CSS: גרדיאנטים, פינות מעוגלות, צללים.

## איך עוברים לשם

לא בבת אחת, ולא ידנית. הדרך שעבדה לקלפים, לאמנדה ולאייקונים היא אותה דרך:
**קובץ בריף אחד לכל משפחה, פקודת `pnpm art:*` שמייצרת מה שחסר, ו-`art:process`
שחותך ודוחס.** אפקטים צריכים גם *רצף* — פיצוץ הוא לא תמונה אחת אלא sprite
sheet — וזה ההבדל הטכני העיקרי מכל מה שעשינו עד עכשיו.

סדר שמציע את עצמו, מהנראה-ביותר למטה:

1. **אייקונים** (בעבודה) — נראים בכל מסך, בכל שנייה.
2. **כפתורים ומסגרות** — אותו דבר, ומשנים את כל תחושת המשחק.
3. **רקעי זירה** — יש שלושה ומשתמשים באחד. זול לנצל את הקיים.
4. **אפקטי קרב** — הכי יקר (sprite sheets) והכי מרשים. אחרי שהשאר יושב.
5. **ערפל** — הכי קטן.

## כלל אחד ששווה לשמור

אייקון הוא לא איור קטן. ב-24 פיקסלים פרטים נמרחים — זר דפנה וסלע סדוק נבדקו
ונמרחו. צורה אחת סגורה, קו עבה, צבע שטוח. מה שמופיע גדול (ניצחון, הפסד)
יכול להיות עשיר; מה שמופיע בשורת מידע — לא.
