# להעלות היום — בדיוק מה לעשות

שני דברים, והשני תלוי בראשון. בין הכל: **בערך 40 דקות**, רובן המתנה.

> **למה היום:** השעון של 14 הימים מתחיל כשה-`.aab` עולה למסלול בדיקה
> סגורה, לא כשהמשחק מוכן. כל יום שלא מעלים נוסף בסוף.

---

## שלב 1 · לבנות את ה-`.aab`

פותחים **cmd** (לא PowerShell, לא גיט־באש) בתיקיית הפרויקט ומריצים:

```
scripts\build-android.cmd
```

**בדקתי שכל מה שהוא צריך קיים אצלך:** ה-JDK ב-`C:\Program Files\Microsoft\
jdk-17.0.20.101-hotspot`, ה-SDK ב-`C:\Users\Public\android-sdk`, המפתח
וקובץ הסיסמה ב-`android\`.

### מה יקרה

1. `Preparing the wrapper at C:\Users\Public\amanda-android ...`
   — הוא בונה עותק עבודה בנתיב באנגלית. **זה בכוונה:** ה-Android Gradle
   Plugin מסרב לבנות מנתיב עם תווים לא־אנגליים, ויש אות עברית בשם
   המשתמש שלך.
2. Gradle יורד ורץ. **כמה דקות**, יותר בפעם הראשונה.
3. חתימה.
4. בסוף:

```
Done. Upload this file to Play Console:

    android\app-release-bundle.aab
```

### אם זה נופל

**תעתיק לי את השורות.** בפרט אם אתה רואה את זה:

```
'C:\Program' is not recognized as an internal or external command
```

זה הבאג מה-10 באוקטובר — bubblewrap מרכיב פקודה בלי מרכאות, והרווח
ב-`Program Files` קוטע אותה. הוא תוקן (`android-prepare.cjs` כותב את
הנתיב הקצר ל-`~/.bubblewrap/config.json` בכל ריצה), אבל **מאז לא רצה
בנייה מוצלחת אצלך** — אז זו הפעם הראשונה שהתיקון נבדק באמת.

### לוודא שיצא משהו

```
dir android\app-release-bundle.aab
```

צריך להיות בערך **4–6 MB**. אם הקובץ לא שם — הבנייה לא הצליחה, בלי קשר
למה שכתוב במסך.

## שלב 2 · להעלות, ואז לקחת את טביעת האצבע

האפליקציה כבר קיימת אצלך ב-Play Console עם הליסטינג — אז מדלגים על
היצירה.

### 2א · להעלות למסלול סגור

`Test and release → Testing → Closed testing`

- אם אין מסלול: **Create track**. קוראים לו `alpha`.
- `Create new release` → גוררים לשם את `app-release-bundle.aab`
- **Release name**: `1.0.0 (2)`
- **Release notes**: מספיק שורה. אפשר „גרסה ראשונה לבדיקה.”
- `Next` → `Save and publish` / `Start rollout to Closed testing`

> **אם הוא צועק `Version code 2 has already been used`** — תגיד לי, אני
> מעלה את המספר ב-`android\twa-manifest.json` ואתה בונה שוב. זה שינוי של
> ספרה אחת.

**ברגע שזה עלה — השעון של 14 הימים התחיל.** כל השאר יכול להמשיך אחר כך.

### 2ב · הבודקים

באותו מסך, `Testers` → רשימת אימיילים. **יש לך 7, צריך 12.**

> האימיילים נכנסים ל-Play Console **בלבד**. לא לריפו — `UncleOr/amanda`
> ציבורי.

### 2ג · טביעת האצבע — השלב שנופלים בו

`Test and release → Setup → App integrity`
*(במסכים ישנים: `Release → Setup → App signing`)*

שם יש **שתי** טביעות אצבע, וזו הנקודה:

| | |
| --- | --- |
| **App signing key certificate** | ✅ **זו שצריך** |
| Upload key certificate | ❌ לא זו |

גוגל חותמת מחדש את מה שהעלית במפתח **שלה**. הטלפון רואה את שלה, לא שלך.

תעתיק את **SHA-256 certificate fingerprint** של ה-**App signing key**.
זה נראה ככה — 32 זוגות עם נקודתיים:

```
A1:B2:C3:D4:E5:F6:07:18:29:3A:4B:5C:6D:7E:8F:90:
A1:B2:C3:D4:E5:F6:07:18:29:3A:4B:5C:6D:7E:8F:90
```

**תדביק לי אותו כאן.** אני מכניס אותו ל-`web/.well-known/assetlinks.json`,
דוחף, וה-Actions מעלה אותו לאוויר תוך דקה־שתיים. אחר כך אני בודק מול
הכתובת החיה ומראה לך שזה שם.

(אם אתה מעדיף לבד: להחליף את `REPLACE-WITH-THE-PLAY-APP-SIGNING-FINGERPRINT`
בקובץ ההוא, לשמור על המרכאות, `git push`.)

## למה זה בכלל משנה

האפליקציה היא **אתר עטוף**. אנדרואיד פותח אותה במסך מלא רק אם הדומיין
מצהיר שהוא מכיר אותה — וההצהרה היא הקובץ הזה.

**הסימפטום כשזה לא נכון:** נפתחת **שורת כתובת של דפדפן בראש המסך**. לא
קריסה, לא הודעה — היא פשוט נראית כמו אתר במקום משחק. קל מאוד לפספס את
זה ולחשוב שהכול תקין.

> הקובץ יושב בשורש הדומיין ולא תחת `/play/`. Digital Asset Links מאמת
> מקור שלם, לא נתיב.

## אחרי זה

להתקין מהמייל של הבודק ולבדוק בטלפון אמיתי:

- נפתח **בלי** שורת כתובת? ← `assetlinks` תקין
- הסרטון רץ? המשחק נטען? אפשר לשחק מול הבוט?

**את זה אני לא יכול לבדוק בשבילך** — אין לי טלפון אנדרואיד, והדבר היחיד
שאני יכול לאמת מכאן הוא שהקובץ באוויר ושהתוכן שלו נכון.

חומרי החנות (צילומים, הקלטה, טריילרים) ממתינים לשמות המפלצות
והמיקרוקופי — הם לא חוסמים את ההעלאה הזו.
