# הישגים של Play Games — מה זה דורש

Or: *"כמה זה מסובך לעבור לזה עכשיו? זה מה שביקשתי מלכתחילה, שנהיה מחוברים
בתוך גוגל פליי. אין לי בעיה לחכות לגרסה הבאה, רק לוודא שאפשר להוסיף
בקלות."*

**אפשר, וזה לא קשה. ושום דבר במה שעולה היום לא מקשה על זה אחר כך.**

---

## למה TWA לא יכול

לא עניין של מאמץ — **זה מבני.** TWA הוא לשונית כרום אמיתית שמוצגת בתוך
אפליקציה. אין בה גשר בין ג'אווהסקריפט לקוד אנדרואיד, **בכוונת התכנון** —
זה בדיוק מה שהופך אותה לדפדפן ולא ל-WebView. אז הדף לא יכול לקרוא
ל-Play Games, כמה שלא ננסה.

בדקתי את מה שנבנה: **אפס** התייחסויות ל-`games` או ל-`gms` במניפסט
ובבאנדל.

---

## מה צריך לזוז — וכמה מעט זה

כל העטיפה לאנדרואיד בריפו היא **שלושה קבצים**:

```
android/twa-manifest.json
scripts/android-prepare.cjs
scripts/build-android.cmd
```

**והמשחק לא יודע שהוא רץ באנדרואיד.** חיפשתי תלות — ההתאמה היחידה היא
`assetlinks.test.ts`, בדיקה על קובץ באתר.

אז המעבר הוא **החלפת העטיפה בלבד**: במקום bubblewrap, מעטפת עם WebView
(Capacitor הוא הדרך המתוחזקת) שטוענת את אותה כתובת. המשחק לא זז.

| | |
| --- | --- |
| החלפת העטיפה + בנייה ובדיקה על מכשיר | יום |
| התחברות ל-Play Games + גשר JS↔נייטיב | יום |
| הגדרת ההישגים בקונסולה וחיווט שלהם | חצי יום |
| **סה״כ** | **יומיים-שלושה**, ובדיקה על טלפון שרק אתה יכול לעשות |

## ומה שכבר מוכן בשבילם

האתגרים כבר מדברים באוצר מילים מוגדר של רגעים:

```ts
{ kind: "playCard"; cardId }   { kind: "placeSeries"; seriesId, row }
{ kind: "score"; least }       { kind: "win" }   { kind: "play" }
```

**אלה בדיוק הרגעים שהישג נתלה עליהם** — וכשבאתי לחווט, התברר שרק חלק.
ניחשתי שהחיווט יהיה קריאה אחת בכל מקום שכבר סופר אתגר, וזה היה מפספס את
רובם: אפשר להרוויח "עשרה קלפים" מתיבה שנפתחה במסך הבית, בלי שאף קרב
נגמר ובלי שאף אתגר נספר.

אז החיווט הוא **הוק אחד** (`game/useAchievements.ts`) שצופה בחשבון: כל
דבר שמשנה את האלבום, את הגביעים או את דגל הטוטוריאל מדווח בעצם זה
שהשתנה, לא משנה מי שינה אותו. ושתי נקודות נוספות שהחשבון לא רואה — סוף
קרב (ניצחון, שלישייה, מלך לא נגוע) ושורה אחת ב-`openChest`.

---

## למה להעלות היום לא עולה כלום

אותו `packageId` (`com.asulins.amanda`) ואותו מפתח העלאה ← הגרסה הבאה
היא **עדכון לאותה אפליקציה**, לא רישום חדש. הבודקים נשארים, הדירוג
נשאר, שעון 14 הימים ממשיך לרוץ.

**ההפך נכון:** אם לא נעלה היום, השעון לא מתחיל — ואז Play Games רק
ידחה את הכל בשבועיים.

---

## שתי הסתייגויות אמיתיות

**1 · שתי זהויות.** התחברות ל-Play Games היא חשבון נפרד מהחשבון שלכם
ב-Supabase. ההתקדמות — אלבום, גביעים, יהלומים — תמשיך לשבת אצלנו;
ההישגים ישבו אצל גוגל. ילד שיתחבר ל-Play Games במכשיר אחר יראה שם את
ההישגים אבל לא את האלבום.

זו החלטה, לא באג, וכדאי להחליט אותה **לפני** שמחווטים: או שההישגים הם
קישוט נוסף, או ש-Play Games הופך לזהות הראשית וה-Supabase נקשר אליה.

**2 · WebView זה לא כרום.** זה Android System WebView. על מכשירים
מודרניים כמעט זהה, אבל זה משטח חדש לבדוק עליו. וצריך לשים לב למדיניות
*minimum functionality* של גוגל על עטיפות אתר — הישגים ומשחק אופליין
הם בדיוק הערך המוסף שעונה עליה, אבל זה דבר שכדאי להיות מודעים אליו.

## לסיכום

**אל תעשה את זה עכשיו.** תעלה את ה-TWA, תתחיל את השעון, ותסגור עם הוד
את השמות והמיקרוקופי. Play Games הוא `versionCode 3` — שבוע הבא, יומיים
עבודה, ואפס מחיקה של מה שנעשה.

## ארבעה צעדים, לפי סדר

### 1 · לקשר את המשחק ל-Play Games

`Grow users → Play Games services → Setup and management`

גוגל תיתן **Application ID** — מספר. הוא נכנס ל-`android/capacitor.json`
תחת `playGamesAppId`.

> **בלעדיו האפליקציה קורסת בפתיחה.** לא מזהירה — קורסת. לכן הסקריפט מסרב
> לייצר פרויקט בלי המספר הזה: פרויקט שלא נבנה עדיף על בנייה שבודק מתקין
> ורואה נופלת.

ובאותו מקום — להוסיף את ה-**SHA-1** מתוך
`Release → Setup → App integrity → App signing`. Play Games בודקת את
החתימה; חתימה שגויה מכשילה את ההתחברות **בשקט**, וההישגים פשוט לא מגיעים
לעולם.

### 2 · ליצור את 18 ההישגים בקונסולה

`Play Games services → Achievements`. הטקסט ב-`docs/ACHIEVEMENTS.md`,
האייקונים ב-`store/achievements/`.

לכל אחד גוגל נותנת **מזהה אטום** בצורת `CgkIxxxxxxxxEAIQAQ`. אלה נכנסים
ל-`PLAY_IDS` ב-`game/achievements.ts` — מזהה שחסר שם פשוט לא מדווח, אז אפשר
למלא אותם בהדרגה בלי לשבור כלום.

### 3 · לבנות

```
set KEYPASS=...
scriptsuild-android-cap.cmd
```

### 4 · להעלות כעדכון

אותו `packageId`, אותו מפתח, `versionCode 3` — זה **עדכון** לאפליקציה
שכבר בבדיקה סגורה. הבודקים, שעון 14 הימים והדירוג נשארים.

## ושלוש אזהרות כנות

**התוסף הוא 0.5.0.** `@modbender/capacitor-play-games`, חודש, ובדקתי שהוא
קיים ברישום npm במקום להניח. זה לפני-1.0. ההגנה היא הצורה: כל מה שמחליט
משהו הוא פונקציה טהורה עם מבחנים, והתוסף מגיע דרך `import` דינמי אחד שמותר
לו להיכשל.

**לא הידרתי שורה אחת מזה.** ה-`.cmd` נבדק עד כמה שאפשר בלי להריץ אותו —
הנתיבים קיימים, הסקריפטים תקינים תחבירית, הסירוב על מזהה חסר עובד — אבל
הבנייה הראשונה היא בדיקה אמיתית ראשונה, ויש סיכוי סביר שמשהו ייפול.

**ואם ייפול, זה זול.** תיקיית העבודה נוצרת מאפס בכל הרצה מתוך
`android/capacitor.json`. למחוק ולהריץ שוב לא עולה כלום חוץ מזמן.
