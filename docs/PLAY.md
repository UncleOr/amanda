## 1. הדומיין

### למה בכלל צריך

ה-TWA מאמת את עצמו מול **מקור (origin) שלם**, דרך קובץ בכתובת
`https://הדומיין/.well-known/assetlinks.json`. היום האתר יושב ב-
`uncleor.github.io/amanda/` — והמקור שם הוא `uncleor.github.io`, שמשותף לכל
פרויקט אחר שיהיה לך שם. **אי אפשר לבנות TWA אמין על מקור משותף.**

### איפה לקנות — ורסל

מבין השניים שיש לך: **ורסל**, ולא הוסטינגר. שלוש סיבות:

1. **אם הדומיין נופל, האפליקציה נופלת.** היא *היא* האתר. לכן מחיר החידוש
   חשוב יותר ממחיר השנה הראשונה, והמודל של הוסטינגר הוא בדיוק הפוך —
   זול בהתחלה, יקר בחידוש. ורסל גובה בערך את העלות בשתיהן.
2. **ורסל גם תארח את הקליינט**, אז הדומיין, התעודה והפריסה הם מקום אחד
   במקום שלושה.
3. **אפשר לקבוע Headers.** GitHub Pages לא נותן. את `assetlinks.json` צריך
   להגיש כ-`application/json` ובלי קאשינג אגרסיבי, והמאמת של גוגל קפדן.

> אם לא אכפת לך לפתוח חשבון נוסף, **Cloudflare Registrar** הוא הזול ביותר
> לאורך זמן (מחיר עלות, בלי תוספת חידוש). אבל ורסל זה חשבון שכבר יש לך,
> וההפרש הוא כמה דולרים בשנה.

> ⚠️ **השרת לא עובר לוורסל.** פונקציות serverless לא מחזיקות WebSocket פתוח
> לאורך משחק. השרת נשאר איפה שהוא — זה כתוב ב-[DEPLOY.md](DEPLOY.md).

### איזה שם

הכלל: **הדומיין הוא של המשחק, לא של המשפחה.** כל המקור הופך לאפליקציה,
אז אם `asulins.com` יהיה הדומיין, אי אפשר יהיה לשים שם אתר משפחתי לצידו.

מועמדים לבדוק זמינות (אתה בוחר, זה שמות):

- `amandathegame.com`
- `amandacards.com`
- `playamanda.com`
- `amanda.game` — יקר יותר, אבל קצר

### מה להגדיר אחרי הקנייה

| איפה | מה |
| --- | --- |
| 👤 Vercel → Add New → Project | לחבר את הריפו `UncleOr/amanda` |
| 👤 Build Command | `pnpm --filter @amanda/client build` |
| 👤 Output Directory | `apps/client/dist` |
| 👤 Environment Variables | `VITE_BASE_PATH` = `/` |
| 👤 Environment Variables | `VITE_SERVER_URL` = `wss://` + כתובת השרת |
| 👤 Domains | הדומיין שקנית, גם apex וגם `www` |

🤖 אחרי זה אני בודק ש-`https://הדומיין/.well-known/assetlinks.json` נטען.

## 3. הסדר

```
👤 לקנות דומיין            ─┐
👤 לחבר ורסל                ├─ אפשר היום
👤 12 אימיילים של בודקים   ─┘
         │
🤖 לארוז TWA (bubblewrap)   ← מחכה לדומיין חי
         │
👤 להעלות AAB למסלול סגור
         │
👤 להעתיק את טביעת האצבע (SHA-256) מ-Setup → App signing
         │
🤖 לשים אותה ב-assetlinks.json ולפרוס
         │
👤 להזמין את 12 הבודקים     ← כאן מתחיל השעון של 14 יום
         │
         ⋯ 14 ימים רצופים, ואנחנו ממשיכים ללטש כל הזמן ⋯
         │
👤 Production
```

> **למה הליטוש לא מעכב:** האפליקציה היא האתר, עטוף. כל פריסה של האתר מגיעה
> למי שכבר התקין, בלי העלאה חדשה לפליי. השעון של 14 היום הוא הדבר היחיד
> שאי אפשר לדחוס — לכן הוא מתחיל ראשון.

### ⚠️ טביעת האצבע — הסדר הזה הפוך ממה שמרגיש נכון

`assetlinks.json` **לא יכול להיות מוכן לפני ההעלאה הראשונה**, כי טביעת
האצבע נוצרת על ידי Play App Signing רק כשהחבילה מגיעה. עד שהיא שם, ה-TWA
יציג שורת כתובת של דפדפן בראש המסך. **זה תקין ולא באג.**
